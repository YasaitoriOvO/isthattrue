# koishi-plugin-isthattrue

Koishi 4 插件，Node.js >= 22。@机器人后使用 `是真的吗`、`is that true`、`核验事实`、`求真`，随后填写待核查内容；也支持引用一条文本消息后发送触发词。必须真实 @当前机器人，不响应纯文本昵称。

例如：`@机器人 核验事实 长城能从月球上用肉眼看到`。

## 配置和运行

运行 `npm install`、`npm run build`，将插件作为本地依赖安装到 Koishi 项目，在控制台启用 `isthattrue`。

配置 `endpoint`（Chat Completions API 根地址，通常以 `/v1` 结尾）、`apiKey`、`model`（必须支持工具调用）、`searchProvider`（tavily / brave / serper）、`searchKey`。`timeout` 为整次核查的超时毫秒数，默认 60000。

在 Koishi 工作目录创建 `data/text-censor/censor.txt`，每行一个敏感词，支持以 # 或 // 开头的注释；或用 `dictionary` 配置其他路径。插件会检查文件存在且非空，否则启动失败，避免误以为已开启过滤。词库修改后重启插件。

直接使用 text-censor 同款底层库 `@q78kg/mint-filter`，发送前把命中词替换为 `*`，继续发送。需要自行提供词表。插件不注册或依赖 Censor 服务，可与已启用的 text-censor 共存，过滤仅作用于本插件的回复。

有效请求开始后先回复“核查中”，再搜索并让模型依据搜索摘要核查；模型最多追加两轮工具调用，每轮最多三个搜索。没有结果则明确说明无法核验。输出通常约 500–900 字，包含核查结论、逐项分析、证据局限，不展示来源名称、编号或链接，简单问题可缩短；没有抓取完整网页，引用真实性与核查质量仍依赖搜索结果和模型。所有输出先完整生成、过滤，再按纯文本发送，不流式发送。

`npm test` 运行离线测试；真实 API 联调需要自己的 LLM 与搜索密钥。

## 调试日志

控制台开启 `debug`（默认关闭）后，在 `isthattrue` 日志中查看请求编号、搜索提供商及结果数量、LLM 轮次及工具调用数、HTTP 状态与耗时、替换情况及发送长度。使用 info 级别输出带 `[debug]` 标记的日志，无须调整全局日志级别。不记录正常请求的正文或完整回复。

无论 debug 是否开启，核查失败都会记录错误堆栈、底层 cause，以及 API 返回的错误响应（日志最多 12000 字符），同时脱敏配置的密钥和常见认证字段。群内仍只发送简短失败提示。第三方错误响应可能包含业务内容，分享日志前请检查。

## 自定义选项

以下均可在 Koishi 插件配置面板修改，未设置时保持原有行为。

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| triggers | 是真的吗 / is that true / 核验事实 / 求真 | 触发词列表，普通文本匹配；空列表不触发 |
| requireMention | true | 是否必须 @当前机器人 |
| useQuote | true | 正文为空时使用引用消息 |
| progressMessage | 核查中 | 开始提示，空字符串关闭 |
| errorMessage | 核验失败，请稍后重试或联系管理员检查 API 配置。 | 失败提示，空字符串关闭，仍记录错误 |
| responseStyle | detailed | detailed 约 500–900 字；brief 约 150–300 字，由模型尽量遵循 |
| extraPrompt | 空 | 附加语气、重点等回复要求 |
| searchCount | 5 | 单次搜索结果上限，1–10；服务可能返回更少 |
| maxToolRounds | 2 | 追加搜索轮数，0–5；每轮最多 3 次；首次搜索始终执行 |
| maxTokens | 3000 | 模型单次输出 token 上限，256–16000，需服务支持 |
| maxInputLength | 4000 | 待核查文本长度上限，100–20000 |
| replacement | * | 单个敏感词替换字符 |

提示语和模型回复都会经过敏感词过滤。提高搜索轮数和输出长度可能增加费用与耗时，必要时同步调整 timeout。

## 图片核查

发送 `@机器人 求真` 并附上图片，或引用带图片的消息发送 `@机器人 是真的吗`；也可以附加问题，例如“这张图里的新闻是真的吗”。先由视觉模型提取可见文字及事实主张，再通过 websearch 搜索证据并输出核查结果。图片观察不作为已证实事实，无明确主张时会提示补充。

- `imageEnabled`：默认 true，启用图片核查。
- `visionModel`：识图模型名，留空使用主模型，共用 endpoint 和 apiKey；必须支持 Chat Completions 的 image_url 输入。
- `maxImages`：默认 3，范围 1–6，超出会提示减少图片，不静默忽略。

默认由插件下载 HTTP(S) 图片并以 Base64 上传模型，支持 PNG/JPEG/GIF/WebP 和对应的 data URL；不支持本地文件、视频或反向搜图。临时链接过期、防盗链或下载到 HTML 时会明确报错。下载拒绝本地和内网地址，并限制大小与重定向次数。`imageTransport` 默认 inline，可切换 url 直接传链接（需要模型服务支持读取远程链接）。`imageMaxBytes` 默认 10000000，限制单张图片大小。视觉模型无法可靠鉴定图片真伪，来源、时间和地点仍需外部证据。识图与搜索共用 timeout，必要时调大。引用图片同样受 useQuote 控制，识图结果经过敏感词过滤后才发送。
